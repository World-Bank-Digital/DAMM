# The automated research pipeline

*Thread 2's build: the vendor audition and the per-indicator research orchestrator, with
the gates that stand between a vendor's answer and a recorded row. Everything here
implements decisions already settled in `DAR-Studio-Automation-Design.md`; where a file
makes a decision mechanical, it says which one in its own docstring.*

---

## What is here

| File | What it is |
|---|---|
| `vendors.py` | The only place an outside call is made. Keys, metering, pricing, tiers, quote verification. |
| `prices.json` | Unit prices. Usage counts are recorded exactly; dollars are derived, so a wrong price is a one-line correction rather than a re-run. |
| `cell_schema.py` | The research cell — one schema and one prompt, shared by the audition and the orchestrator. |
| `gates.py` | The gates: isolation, quote, tier, construct, prerequisite, coherence, argument. |
| `countries.json` | Country isolation data (C7). Adding a name or an adjectival form is a data edit. |
| `run_audition.py` | The thirteen-cell vendor audition, with `--rescore` to re-apply a corrected rule to saved evidence. |
| `audition_cells.json` | The thirteen cells, every one drawn from the verified assessments. |
| `research_orchestrator.py` | Per-indicator research for one country → an engine input. |
| `compare_shadow.py` | The acceptance test: a shadow run against the verified assessment, row by row. |
| `smoke_vendors.py` | Nine live checks over every vendor path. Run this first when something looks wrong. |
| `AUDITION-RESULTS.md` | The measurement. Regenerated by the runner. |
| `VENDOR-DECISION.md` | The judgment made on it. Hand-written; not regenerated. |

## Running it

Everything runs under `../../../.venv`, which carries the vendor SDKs. The rest of the
pipeline still runs on the system `python3`; the virtualenv exists so that installing
three SDKs could not disturb a verified toolchain.

```bash
cd gauntlet/loop-1/research_pipeline
../../../.venv/bin/python smoke_vendors.py                    # 9 checks, a few cents
../../../.venv/bin/python run_audition.py --ceiling 40        # ~$9, ~20 min
../../../.venv/bin/python run_audition.py --rescore           # free: re-score saved evidence
../../../.venv/bin/python research_orchestrator.py \
    --country Egypt --iso EGY --out EGY_shadow --ceiling 500  # 59 rows
python3 ../engine_v17.py ../EGY_shadow_input.json ../EGY_shadow.json Egypt
../../../.venv/bin/python compare_shadow.py \
    --shadow EGY_shadow --oracle EGY_v17 --country Egypt
```

A run checkpoints after every row. `--resume` picks up where it stopped; `--rows 2.1,1.8`
researches a named subset, which is the cheap way to probe a change.

## Things worth knowing before changing anything

**The oracle is not to be written to.** `EGY_v17.json` and `NGA_v17.json` are the test
oracle. The orchestrator never reads them and the comparison never writes to them. A
shadow run goes to its own `--out` basename throughout.

**Correcting a scoring rule does not require re-running.** Both the audition and the
orchestrator checkpoint the retrieved pages alongside the answers, because those pages
are the evidence a fabrication claim is made against. `run_audition.py --rescore`
re-applies the current rules to the run that already happened. Two of the audition's own
findings were corrections to the scoring rather than to a vendor, and both were applied
this way without a single new vendor call.

**Budget exhaustion raises; it never degrades.** `vendors.BudgetExhausted` stops the run
and the orchestrator refuses to write an engine input that is missing rows. A partial
input would score as though the missing rows had been looked for and not found, and a
budget-induced gap that reads like a real one is how Nigeria's 21 phantom gaps happened.

**Never let a text rule run over a URL.** `standalone` and `americanize` are applied to
values, notes and source titles, never to `url`. Two live citations contain the exact
strings the American-spelling rules rewrite.

**Derivation rules have one home each.** The qualitative ladder lives in
`build_inputs.ladder_level`; the machine-fetchable T1 series map lives in
`machine_pass.SERIES`. Both files were made importable so this pipeline shares them
rather than carrying a second copy that would drift. Both countries' verified inputs
regenerate byte-identical, and `verify_end_to_end.py` checks that they still do.

**Quote verification catches invention. It does not catch construct substitution.** The
audition demonstrated both halves of this: no entrant asserted a value it could not
quote, and one entrant recorded a raw enrolment count against an indicator whose name
ends in "(%)", fully quote-verified. The construct gate (C3) and the prerequisite bar
(C4) are what catch the second kind, and they cannot be collapsed into the quote check.

## What is not here

Automated Gate 2, the broad and international scans, the app's job queue and worker are
Thread 3. The foresight and DAR generators and their QC gates are Thread 4. Nothing here
runs a refutation pass, which is the main reason a shadow run holds more rows than the
hand-run assessments did — and why the shadow figures should be kept as the
before-measurement for whether Gate 2 earns its 15% of the budget.
