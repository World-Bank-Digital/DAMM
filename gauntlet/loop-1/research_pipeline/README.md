# The automated research pipeline

*Thread 2's build: the vendor audition and the per-indicator research orchestrator, with
the gates that stand between a vendor's answer and a recorded row. Everything here
implements the Stage 1 research surface; where a file makes a decision mechanical, it
says which one in its own docstring.*

> **Normative workflow supersession — 26 August 2026.** This directory is one component of
> the eight-stage contract in `workflow/DAR-CANONICAL-WORKFLOW.md` and
> `workflow/dar-workflow-v1.json`, which supersedes conflicting orchestration language in
> this README and `DAR-Studio-Automation-Design.md`. The canonical stages include separate AI
> and digital-agriculture assessment and investment-options/cost-benefit analysis. Optional
> documents are frozen before launch and otherwise trigger autonomous fallback. An active run
> requires no human confirmation, upload, retry choice, or budget top-up. The independent
> automated challenge belongs to Stage 1; human G1/G2/G3 occur after Stage 8 and govern review,
> Final promotion, and publication. Draft generation is allowed before review. The four DAMM
> prohibitions remain unchanged.

## Running it

Everything runs under `../../../.venv`, which carries the vendor SDKs. The rest of the
pipeline still runs on the system `python3`; the virtualenv exists so that installing
three SDKs could not disturb a verified toolchain.

```bash
cd gauntlet/loop-1/research_pipeline
../../../.venv/bin/python smoke_vendors.py                    # 9 checks, a few cents
../../../.venv/bin/python run_audition.py --ceiling 40        # ~$9, ~20 min
../../../.venv/bin/python run_audition.py --rescore           # free: re-score saved evidence
../../../.venv/bin/python research_orchestrator.py \
    --country Egypt --iso EGY --out EGY_shadow --ceiling 500  # 59 rows
python3 ../engine_v17.py ../EGY_shadow_input.json ../EGY_shadow.json Egypt
../../../.venv/bin/python compare_shadow.py \
    --shadow EGY_shadow --oracle EGY_v17 --country Egypt
```

A run checkpoints after every row. `--resume` picks up where it stopped; `--rows 2.1,1.8`
researches a named subset, which is the cheap way to probe a change.

The canonical application entry point is the coordinator, not an individual stage script:

```bash
python3 run_workflow.py \
    --country Egypt --iso EGY --out ../EGY_2026_workflow \
    --legacy-out EGY_2026 --ceiling 500 --resume
```

`--resume` is safe on the first launch and resumes only the same hash-verified immutable
run after an interruption. Optional uploads, when present, must be frozen in the canonical
uploads manifest before this command starts. No upload, approval, retry choice, or budget
decision is requested after launch. Stage 8 verifies and packages the manifest, the exact
Stage 1 engine input reviewed later at human G1, each extracted text file, and each original
upload byte-for-byte; a missing, changed, escaping, or symlinked input is a terminal integrity
failure.

## Things worth knowing before changing anything

**Read extractive source text before asking a second service for the same page.**
Stage 1 (including automated challenge), country/international scans, AI assessment, and
foresight request bounded Exa page text with their existing discovery searches. The shared
`vendors.read_source` uses that extractive text when at least 200 non-padding characters
are available; otherwise it requests one citation URL through Exa Contents, text only,
with no subpages. An authoritative short text response can fall through to Jina Reader.
Generated summaries and Perplexity prose
are never source evidence. Source URLs, tiers, country isolation and quote verification
remain mandatory, and each retrieved page identifies its retrieval provider.

The Contents request reserves its full $0.001 one-page bound before transport and journals
its response before exposing evidence. The sole status ID and returned URL must both match
the requested URL. Exa's nonempty document ID may differ, as observed in a live PDF
response; it is not used as the source URL. A changed returned URL still stops conservatively
instead of inheriting the original publisher's tier. Only documented, exact source-level Exa error tuples permit
another selected page to satisfy the row. Authentication, throttling, unknown errors,
malformed responses and conflicting cost estimates remain terminal across restart. If every
selected source is unavailable, Stage 1 stops without publishing a country evidence gap.
Invalid Contents responses retain only a fixed validation category in the private paid
ledger, distinguishing cost, envelope, status, identity, text and source-error failures.
The category survives restart; raw provider responses, URLs and error strings are not
included. Older checkpoints without a category still stop and cannot be reissued. This
instrumentation does not determine response acceptance or make an unknown source failure
safe to retry. A terminal `retrieval_usage_missing` record from an older build does not
identify which validation failed; diagnose it as unclassified until independent evidence
is available.

See the [Contents API](https://exa.ai/docs/reference/get-contents),
[pricing](https://exa.ai/docs/reference/pricing) and
[error codes](https://exa.ai/docs/reference/error-codes), verified 2026-09-05; the
Contents document-ID distinction was reproduced with a bounded live request on 2026-09-06.

**A Reader rejection is not proof of an evidence gap.** Only the enumerated 40904 and
42203 tuples, plus the strictly validated, exact target-bound 42206 no-content response,
are source-local. Another selected source can satisfy the row. Authentication, credit,
throttling, service errors and all ambiguous or unknown assertions remain durable terminal
outcomes. Fixed private diagnostic categories aid investigation without keeping provider
prose or secrets. Every started request remains accounted for; a checkpoint must not replay
an identical completed or unresolved paid request. This policy does not make failed runs
eligible for resume, or authorize a live smoke test. Use synthetic fixtures for repair work;
any new paid case requires separate authorization.

**The oracle is not to be written to.** `EGY_v17.json` and `NGA_v17.json` are the test
oracle. The orchestrator never reads them and the comparison never writes to them. A
shadow run goes to its own `--out` basename throughout.

**Correcting a scoring rule does not require re-running.** Both the audition and the
orchestrator checkpoint the retrieved pages alongside the answers, because those pages
are the evidence a fabrication claim is made against. `run_audition.py --rescore`
re-applies the current rules to the run that already happened. Two of the audition's own
findings were corrections to the scoring rather than to a vendor, and both were applied
this way without a single new vendor call.

**Budget exhaustion raises; it never degrades or waits for a top-up.**
`vendors.BudgetExhausted` stops this component and the orchestrator refuses to write an
engine input that is missing rows. At canonical-workflow level, bounded retry and declared
fallback may run within the preauthorized ceiling; unresolved exhaustion is a terminal
failure, never a pause for human input. A partial input would score as though the missing
rows had been looked for and not found, and a budget-induced gap that reads like a real one
is how Nigeria's 21 phantom gaps happened.

**Never let a text rule run over a URL.** `standalone` and `americanize` are applied to
values, notes and source titles, never to `url`. Two live citations contain the exact
strings the American-spelling rules rewrite.

**Derivation rules have one home each.** The qualitative ladder lives in
`build_inputs.ladder_level`; the machine-fetchable T1 series map lives in
`machine_pass.SERIES`. Both files were made importable so this pipeline shares them
rather than carrying a second copy that would drift. Both countries' verified inputs
regenerate byte-identical, and `verify_end_to_end.py` checks that they still do.

**Quote verification catches invention. It does not catch construct substitution.** The
audition demonstrated both halves of this: no entrant asserted a value it could not
quote, and one entrant recorded a raw enrolment count against an indicator whose name
ends in "(%)", fully quote-verified. The construct gate (C3) and the prerequisite bar
(C4) are what catch the second kind, and they cannot be collapsed into the quote check.

## Boundary with DAR Studio

The analytical stage runners and canonical coordinator live here. DAR Studio owns durable
queueing, worker leases, pre-launch file extraction, progress display, and download serving.
It launches `run_workflow.py` and consumes its versioned manifests; it must not recreate the
stage order, infer completion from filenames, or introduce an active-run human gate.

`research_orchestrator.py` alone does not run the refutation pass; `diagnostic_stage.py` runs
that independent automated challenge before scoring. The automated challenge is not human G2:
G2 is a post-completion peer-review control. Shadow figures therefore remain a useful
before-measurement, but they do not define a separate workflow stage or fixed budget share.
